# 五言古诗生成系统

这是一个面试实战题的完整实现：输入任意 `topic`，系统返回一首标题合法、四句五言、韵脚合规的古诗。

这个项目想回答的核心问题不是“怎么让大模型写一首诗”，而是：

> 当大模型的输出不可完全信任时，怎样设计一条可校验、可修复、可观测，并且一定能返回合法结果的生成链路？

在线体验：[五言试验台](https://wuyan-poet-lab.fizzy-stork-4445.chatgpt.site)

## 方案概述

系统把工作拆给两个角色：

- **大模型负责创作**：理解“猫猫侦探”“AI 时代的孤独”等开放主题，组织意象和语言。
- **确定性程序负责验收**：检查标题、句数、字数、字符和韵脚。程序说通过，结果才可以交付。

如果诗稿不合格，校验器通过 Tool Call Result 明确告诉模型：哪一句错了、当前韵母是什么、目标韵母是什么、可以使用哪些末字，以及哪些正确句子必须保留。模型最多修改四轮；仍不合格或 API 异常时，系统使用预先校验过的本地诗作兜底。（时间限制至选择了一首诗，更优可以选择本地诗库，通过主题选取更合适的诗文）

```text
topic
  │
  ▼
大模型创作并调用 submit_poem
  │
  ▼
确定性校验器 ── 合格 ────────────────► 返回
  │
  └─ 不合格：返回错误句、目标韵和建议末字
                  │
                  ├─ 预算内：模型定向修改，再次提交
                  │
                  └─ 超过预算或 API 失败：本地诗库兜底
                                            │
                                            ▼
                                      再做一次完整校验
                                            │
                                            ▼
                                           返回
```

## 需求理解

对返回结果执行以下硬约束：

| 约束 | 判定方式 |
| --- | --- |
| 标题 | 2～8 个汉字 |
| 结构 | `lines` 恰好包含四句 |
| 字数 | 每句恰好五个汉字 |
| 字符 | 标题和诗句不能出现标点、空格、数字或英文字母 |
| 韵脚 | 第一、二、四句末字韵母相同，第三句使用不同韵母；忽略声调 |
| 异常 | 输入、模型输出或 API 状态异常时，最终结果仍满足以上约束 |

返回格式：

```json
{
  "topic": "月色",
  "title": "月下清辉",
  "lines": [
    "清辉照晚窗",
    "疏影覆寒霜",
    "客梦随云远",
    "天涯共月光"
  ]
}
```


## 核心设计

### 1. 强制模型调用 `submit_poem`

模型不能直接宣布最终答案，而要把候选诗作为工具参数提交：

```json
{
  "title": "灵猫探案",
  "lines": ["玄猫夜叩门", "轻爪踏霜痕", "鼠迹迷深巷", "功成隐月门"]
}
```

工具参数 Schema 先限制基本形状，正式校验器再独立验证全部约束。这样做的价值是让“生成”和“验收”成为两个清楚的阶段，也让失败原因可以结构化地送回模型。

### 2. 校验器是最终裁判

`validator.py` 不调用模型，只做可重复的确定性判断：

1. 检查对象字段类型；
2. 检查标题长度与字符范围；
3. 检查是否恰好四句；
4. 检查每句是否恰好五个汉字；
5. 使用 `pypinyin` 提取末字韵母；
6. 检查第一、二、四句同韵且第三句转韵。

校验器会收集全部错误，而不是发现第一个错误就停止，因此一次修复可以解决多个问题。

### 3. Tool Result 必须能指导下一步

只返回 `rhyme_mismatch` 不够清楚。现在的反馈会给出逐句诊断：

```json
{
  "incorrect_lines": [4],
  "preserve_lines": [1, 2, 3],
  "recommended_rhyme_final": "en",
  "recommended_end_chars": ["门", "痕", "尘", "人", "深", "身", "根"],
  "errors": [
    {
      "line_index": 3,
      "message": "第4句末字『新』的韵母是 in，正确目标韵母是 en"
    }
  ],
  "instruction": "只重写第4句，第1、2、3句保持原样"
}
```

目标韵在多轮修复中保持不变，避免模型改完第一句后，下一轮又跟着新的第一句切换目标。

### 4. 有限重试，而不是无限自我修复

每次模型调用都会增加延迟和 Token 成本。本实现最多允许四次工具提交，任一轮通过立即停止。有限预算同时保证：

- 不会因为模型持续犯同一个错误而无限循环；
- 最坏延迟和调用次数可以估算；
- 失败后能够及时进入可靠兜底。

### 5. 本地兜底保证最终合法

“任何情况下都返回合法结果”不能依赖另一次网络请求。本地诗库保存的是完整诗作，不在运行时随机拼词；每一首兜底诗都会通过同一个正式校验器。

系统先用简单关键词选择相近主题；无法分类时返回通用诗作。兜底优先保证接口契约，文学相关性可能下降，这个取舍会在 Trace 中明确标记，而不会伪装成模型结果。

## 可观测性设计

除了最终诗作，系统还记录每次运行的完整路径：

- 使用的模型；
- 每轮请求和工具提交；
- 候选诗与逐句校验结果；
- 最终采用模型结果还是本地兜底；
- 输入、输出和总 Token；
- 估算成本与端到端耗时。

Web 界面分成两个页面：

- **试诗页**：只关注输入和最终结果；诗成之前不展示成果区，成功后自动下滑到诗笺。
- **运行行迹页**：用于开发、演示和解释决策过程。后台会检查新数据，但内容未变化时不会重新绘制页面。

本地 Python 版本的 Trace 保存在进程内存中，适合开发调试；公网版本使用持久化数据库，服务重启后记录仍然存在。

## 文学质量评判

硬约束和文学质量不能混为一个分数：

- 硬约束不满足，候选直接淘汰；
- 只有合法候选才有资格比较文学质量；
- 模型负责主题理解、起承转合、意象和自然表达；
- 当前不在关键路径增加一次 LLM-as-judge，避免延迟和成本翻倍。

这里的优先级是：**先保证一定正确，再在合法集合中追求更好。**

## 异常策略

以下情况都会被边界捕获，并进入兜底路径：

- 没有配置 API Key；
- 网络失败、超时、限流或上游服务错误；
- 模型没有调用工具；
- 工具参数不是合法 JSON；
- 诗稿结构、字符、字数或韵脚不合格；
- 四轮修复后仍未通过。

日志和 Trace 不记录 API Key。公开部署时 Key 只存在服务器的秘密环境变量中，不会发送到浏览器。

## 测试策略

测试不是只验证几个示例，而是围绕“不变量”组织：

- 标题长度边界：1、2、8、9 个汉字；
- 诗句数量：3、4、5 句；
- 单句长度：4、5、6 个汉字；
- 标点、空格、数字、英文和 emoji；
- 同韵、异韵、第三句错误押韵；
- 首稿失败后工具反馈与定向修复；
- 模型空响应、异常和未配置 Key；
- 任意 Unicode `topic` 最终都返回合法诗作。


## 代码结构

```text
poet/
├── src/poet/
│   ├── service.py       # 总流程：模型、校验、修复、兜底
│   ├── llm.py           # OpenRouter 与 submit_poem 工具循环
│   ├── validator.py     # 全部硬约束
│   ├── rhyme.py         # 韵母提取与可用韵脚
│   ├── fallback.py      # 确定性本地兜底
│   ├── trace.py         # 运行事件、Token、成本与耗时
│   └── data/            # 已校验诗库与主题映射
├── web/                 # 无框架本地试验台
├── webapp.py            # 本地 HTTP 接口
├── main.py              # 最小可运行入口
└── site/                # 公网版本：Web UI、云端 API、持久化 Trace
```

核心 Python 代码保持扁平，便于面试时从 `generate_poem` 顺着调用链阅读。`site/` 是部署适配层，因为云端运行环境与本地 Python 不同；它沿用相同的工具协议和约束规则。

## 本地运行

要求 Python 3.11+。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
```

复制配置并填入 OpenRouter Key：

```bash
cp .env.example .env
```

```dotenv
OPENROUTER_API_KEY=你的Key
POET_MODEL=~deepseek/deepseek-v4-flash-latest
POET_TOOL_MAX_ATTEMPTS=4
```

命令行试用：

```bash
.venv/bin/python main.py "猫猫侦探"
```

启动 Web 试验台：

```bash
.venv/bin/python webapp.py --port 8765
```

访问：

- `http://127.0.0.1:8765/`
- `http://127.0.0.1:8765/traces`
